# MUD RACING — квадроспорт, гонки с водными препятствиями

Браузерная аркадная игра: парные заезды квадроциклов по трассе из трёх грязевых ванн.

## Структура проекта

```
index.html        разметка + CSS интерфейса, подключает скрипты
img/hero.jpg      фото для экрана «Готов?» (в сборку встраивается как data-URI)
img/judge.jpg     фон вопроса по регламенту («Экстрим»)
img/fail.jpg      фон экрана «Утонул» («Экстрим»)
questions.json    вопросы по регламенту для «Экстрима»
src/core.js       физика, трасса, ИИ, жеребьёвка (без DOM — работает и в Node)
src/store.js      имя игрока, рекорды в localStorage, запросы к серверу
src/sound.js      процедурный звук на WebAudio (двигатель, всплески, светофор)
src/render.js     отрисовка сцены на canvas 2D: трасса, квадроцикл, HUD
src/game.js       состояния игры, интерфейс, ввод, чемпионат
build.py          сборка в один автономный файл + файлы PWA
pwa/              PWA: манифест, service worker, иконки (make-icon.html — генератор иконки)
server/           Cloudflare Worker + D1: общая таблица рекордов
```

## Запуск

Открыть `index.html` в браузере — сервер не обязателен.

Если браузер блокирует загрузку скриптов с `file://`:

```bash
python3 -m http.server 8000
# затем http://localhost:8000
```

## Сборка в один файл

```bash
python3 build.py    # создаёт docs/index.html
```

Сборка встраивает все скрипты, фотографии (`img/*.jpg` → base64) и
`questions.json`, поэтому итоговый файл не зависит ни от папки `src/`,
ни от `img/`, ни от интернета (кроме общей таблицы рекордов).

## Приложение на телефоне (PWA)

Сборка в `docs/` — устанавливаемое веб-приложение: `build.py` вставляет в
`docs/index.html` манифест и иконки и копирует из `pwa/` файлы
`manifest.webmanifest`, `sw.js` (с номером сборки) и `icons/`.

- Установка: Android/Chrome — кнопка «📲 Установить игру как приложение»
  в меню; iPhone — Safari → «Поделиться» → «На экран „Домой“» (подсказка
  в меню). Установленная игра открывается на весь экран.
- Инструкция с картинками для игроков: `pwa/install.html` → 
  https://levchenkodenis63.github.io/mudracing/install.html (вкладка выбирается
  по телефону; ссылки `install.html#ios` и `install.html#android` открывают нужную сразу).
- Service worker: сначала сеть, без сети — из кэша, поэтому игра работает
  офлайн, а новая версия подхватывается при следующем запуске с интернетом.
  Запросы к серверу рекордов не кэшируются.
- Работает только по https (GitHub Pages) — с `file://` и в dev-версии
  PWA выключена.

## Имя игрока и рекорды

`src/store.js` держит всё в `localStorage` под ключом `mudracing.v1`:

```js
{ name: "Денис", records: [ { n, t, d, b, p, ts }, ... ] }
```

- `n` — имя, `t` — сумма четырёх заездов, `d` — уровень соперников,
  `b` — лучший круг, `p` — занятое место, `ts` — метка времени.
- Хранится не более 20 лучших результатов, сортировка по времени.
- Имя чистится в `cleanName`: только буквы, цифры, пробел, дефис, точка,
  подчёркивание; всё, что похоже на HTML — отбрасывается целиком.
- Все записи проходят через `sane()`, поэтому битые данные из хранилища
  не ломают вёрстку.
- Если `localStorage` недоступен (приватный режим, запрет cookies),
  игра работает в памяти и честно пишет об этом на экране рекордов.

## Общая таблица рекордов (сервер)

Кроме локальных рекордов есть общая таблица всех игроков: Cloudflare Worker
+ база D1 (`server/`). Пока в `src/store.js` пуст `API_URL`, игра работает
только с локальными рекордами.

- Вкладки **Новички / Любители / Профи / Экстрим / Абсолют** — и для своих рекордов,
  и для общей таблицы. На уровне у каждого игрока одна строка — его лучший
  результат против соперников этого уровня. **Абсолют** — лучший результат
  игрока на любом уровне, с пометкой уровня.
- В общую таблицу уходит только **лучший локальный результат на каждом
  уровне**. Если он меняется (или игрок меняет имя), клиент досылает его
  сам: после чемпионата, при открытии меню и вкладки «Все игроки». Рекорды,
  поставленные до появления сервера, тоже досылаются.
- Игрок определяется случайным id браузера (`mudracing.cid` в localStorage).
- Сервер делает только проверку на корректность: имя чистится тем же
  правилом, что в `cleanName`, сумма должна быть от 60 до 368 с.
  Защиты от накрутки нет — проект для своих.

### Развёртывание (один раз)

```bash
cd server
npx wrangler login                       # вход в Cloudflare через браузер
npx wrangler d1 create mudracing         # вписать database_id в wrangler.toml
npx wrangler d1 execute mudracing --remote --file=schema.sql
npx wrangler secret put ADMIN_TOKEN      # токен для удаления записей
npx wrangler deploy                      # выдаст адрес https://mudracing-scores.<...>.workers.dev
```

Затем вписать этот адрес в `API_URL` в `src/store.js` и пересобрать
`python3 build.py`.

Миграции живой базы лежат рядом (`migrate-*.sql`); перед применением
сделать копию: `npx wrangler d1 export mudracing --remote --output=backups/<имя>.sql`.

### API

- `GET /scores?diff=<easy|normal|hard|extreme|all>&me=<cid>&offset=<n>` — 20 строк
  уровня (или абсолюта), начиная с `n` (по умолчанию 0), и место игрока.
  В игре — кнопка «Показать ещё» внизу списка.
- `POST /scores` — `{cid, name, diff, total, bestLap, place, ts}`; на уровне
  хранится лучший результат, в ответе — место на уровне и в абсолюте.
- `DELETE /scores/<id>` с заголовком `Authorization: Bearer <ADMIN_TOKEN>` —
  удалить запись (модерация имён).

## Как устроена игра

**Трасса.** Три ванны по 30–36 м, между ними перемычки 3–5 м. Две дорожки,
рельеф каждой генерируется отдельно: в каждой ванне свои ямы и отмели.

**Тяга вместо скорости.** В воде важно попадание в зелёную зону тахометра:
зона сужается с глубиной. Перелив — гидроудар (−25 % скорости), недобор —
пробуксовка, долгий перелив по песку — перегрев и остановка на 1.6 с.

**Регламент.** Жеребьёвка на 4 серии: каждый едет 2 раза по одной дорожке
и 2 раза по другой. При нечётном числе участников в каждой серии кто-то
едет без пары. Победитель — по сумме четырёх времён, фальстарт +2.00 с.

**Экстрим.** Соперники как на «Профи», плюс два правила:

- После жеребьёвки — вопрос по регламенту (случайный из `questions.json`,
  варианты перемешиваются). Верно — допуск к старту, неверно — на главную.
- Заглох в воде — мотор сам не заводится: отпусти газ и нажми снова (не
  раньше `C.RESTART` = 0.8 с). Если мотор стоит в воде `C.DROWN` = 2 с —
  квадроцикл тонет, время заезда `C.TLIMIT` = 90 с. Боты иногда тоже тонут
  (`C.SINK_P`, около 3 % заездов).

Формат `questions.json` (`correct` — номер правильного ответа с нуля):

```json
[{ "question": "Как пенализируется фальстарт?", "answers": ["25 сек", "5 сек", "дисквалификация"], "correct": 1 }]
```

При разработке вопросы подгружаются через `fetch`, поэтому `index.html`
нужно открывать через http-сервер (с `file://` вопрос будет пропущен);
в собранном `docs/index.html` они встроены.

**Параметры в `src/core.js`** (объект `C`): `WATER` — уровень воды,
`FLOAT` — глубина всплытия, `PENALTY` — штраф за фальстарт. Баланс скорости
задаётся в `stepRider` (`vmax`, коэффициенты ускорения) и в `zone()`.

## Управление

- ↑ / W / Space — газ (удерживать)
- на тач-устройствах — палец по экрану или кнопка «ГАЗ»
- Enter — следующий экран

## Технические заметки

- Canvas 2D, без библиотек и внешних запросов. ~16 мс на кадр на десктопе,
  ~20 мс на мобильной эмуляции.
- `src/core.js` работает в Node:

```js
const MR = require('./src/core.js');
const tr = MR.makeTrack(1);
console.log(MR.simRun(tr, 0, 0.9, MR.rng(42)).total.toFixed(2));
```

- Звук запускается после первого касания — ограничение автоплея браузеров.
